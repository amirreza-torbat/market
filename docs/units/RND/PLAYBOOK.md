# شیوه کار `RND`

## اصل توالی

هیچ‌وقت «همه سایت‌ها را با هم» تمام نکنید. ترتیب ثابت است:

1. **شناسایی و هویت** — سایت وجود دارد، چیست، مال کیست
2. **کالبدشکافی یک سایت با روبریک کامل**
3. **سایت بعدی**
4. **ماتریس بین‌سایتی** فقط وقتی حداقل ۳ پرونده accepted دارید
5. **کاتالوگ نکات درست** و پیشنهاد بومی

اگر وسط کالبدشکافی علی‌بابا خواستید ایندیا مارت را هم «سریع» بگویید، نکنید. یک خط در بخش مجهولات بنویسید تا MGT بعداً تسک بدهد.

## مشاهده مستقیم

برای هر صفحه کلیدی:

- URL کامل
- تاریخ و ساعت مشاهده (منطقه زمانی را بنویسید)
- زبان رابط
- ورود کرده بودید یا مهمان
- محدودیت ژئو/تحریم اگر صفحه باز نشد — این خودش یافته است نه بهانه برای حدس زدن UI

اگر صفحه باز نشد: در گزارش `blocked-observation` ثبت کنید. UI را از حافظه یا مقالهٔ ۲۰۱۹ بازسازی نکنید.

## حداقل صفحات هر کالبدشکافی سایت

1. خانه
2. نتایج جستجو / دسته
3. صفحه کالا
4. صفحه شرکت / تأمین‌کننده
5. RFQ یا استعلام (اگر هست)
6. عضویت فروشنده / قیمت
7. مرکز اعتماد / ضمانت معامله / کمک
8. فوتر و لینک‌های قانونی
9. نسخه موبایل یا اپ (اگر در دامنه تسک باشد)

## برچسب‌گذاری جمله

هر پاراگراف تحلیلی باید یکی از این‌ها باشد:

- `واقعیت:` چیزی که در صفحه دیده یا در منبع رسمی آمده
- `فرض:` استنباط شما
- `نکته‌درست:` چیزی که باید برای محصول ما جدی گرفته شود
- `رد:` چیزی که نباید کپی شود و چرا
- `اثر:` واحد مصرف‌کننده

## نوشتن برای ایجنت بعدی

آخر هر گزارش accepted این بلوک اجباری است:

```md
## برای ایجنت بعدی
- این فایل چه چیزی را تمام کرده؟
- چه چیزی را عمداً باز گذاشته؟
- کدام URLها دیگر نباید از صفر دیده شوند مگر بازنگری؟
- اگر بخواهم تعمیق کنم از کدام بخش شروع کنم؟
```

## بسته داده

بعد از pass، فایل جدا در `packages/`:

`packages/<TASK-ID>-to-<UNIT>.md`

محتوا فقط برش مربوط به همان واحد. طراح نباید مجبور شود ۲۰ صفحه استراتژی درآمد را بخواند تا کد رنگ را پیدا کند.

# ENG-002 — ADR پشته فناوری (پیشنهاد نهایی برای build)

- واحد: `ENG` | تسک: `ENG-002` | تاریخ: 2026-09-27
- وضعیت: پیشنهاد نهایی — طبق اختیار واگذارشده صاحب‌کار («همه نقش‌ها») پیش‌فرض build است؛ تا توقف صاحب‌کار معتبر
- قیدها از acceptedها: SSR و ایندکس‌پذیری (SEO-001 A9)، RTL/i18n از روز اول (LOC-001)، داده کارت هرگز ذخیره نمی‌شود (LEG-004)، ledger append-only (FIN-003)، audit همه‌جا (SEC-001)، میزبانی اولیه داده داخل/کنترل‌شده (LEG-004)، SoD و دو-کلید (SEC-001)

## ADR-T1 — Frontend/Full-stack: **Next.js 14 (App Router) + TypeScript + Tailwind CSS**
- چرا: SSR/SSG بومی = A9 سئو؛ پشتیبانی i18n و RTL؛ اکوسیستم؛ یک زبان در کل استک
- ردشده: SPA خالص (نقض SEO-001)؛ PHP/Laravel (سرعت تیم و اکوسیستم تایپ‌محور)

## ADR-T2 — پایگاه داده: **PostgreSQL + Prisma**
- چرا: تراکنش‌های مالی ACID (FIN-002/003)؛ JSONB برای فیلدهای متغیر دسته‌ها (CAT-001)؛ FTS پایه برای جست‌وجو
- ردشده: MongoDB (ledger مالی رابطه‌ای مطمئن‌تر)؛ Multi-DB زودهنگام (پیچیدگی)

## ADR-T3 — جست‌وجو: **Postgres FTS در MVP → Meilisearch در مقیاس**
- چرا: جست‌وجوی D22/D23 با فیلترهای PIM؛ ساده شروع، ارتقای کم‌درد
- ردشده: Elasticsearch زودهنگام (عملیات سنگین)

## ADR-T4 — احراز: **سشن امن + OTP ایمیل/تلفن + TOTP 2FA (نقش‌های مدیریتی اجباری)**
- چرا: SEC-001 (2FA، SoD)؛ RBAC ساده؛ بدون سرویس خارجی وابسته (ریسک تحریم سرویس‌دهنده — CMP-002)
- ردشده: Auth0/Clerk (وابستگی بیرونی و ریسک تحریم برای کاربر ایرانی)

## ADR-T5 — فایل‌ها: **Object storage سازگار S3 (MinIO self-hosted)**
- چرا: اسناد/گواهی‌ها (TRD-014) با دسترسی‌کنترل؛ داده در زیرساخت کنترل‌شده (LEG-004)
- ردشده: S3 عمومی AWS (ریسک تحریم/داده — CMP-002)

## ADR-T6 — اعلان‌ها: **SMTP مستقیم + اعلان درون‌پنلی (X01)؛ پیامک از سرویس داخلی**
- ردشده: سرویس‌های ابری تحریم‌شده

## ADR-T7 — استقرار: **VPS/سرور کنترل‌شده + Docker Compose (MVP) → K8s در مقیاس**
- چرا: LEG-004 (حاکمیت داده)؛ هزینه MVP؛ سادگی عملیات اولیه
- ردشده: ابرهای عمومی آمریکا (تحریم/داده)

## ADR-T8 — پرداخت: **ماژول انتزاعی PaymentProvider**
- چرا: FIN-001/002 — کانال‌ها فقط پس از تأیید CMP/وکیل؛ escrow فقط با نگهدارنده مجاز (LEG-001)؛ تا آن‌ زمان ماژول «ثبت دستی + تطبیق» فعال است
- ردشده: اتصال زودهنگام به هر درگاه بدون تأیید CMP

## نقشه ماژول‌ها (ENG-001) → استک

| ماژول | پیاده‌سازی |
|---|---|
| Identity/Membership | Next.js auth + Prisma User/Membership |
| Catalog/PIM | Prisma Product/Variant/Certificate + admin UI |
| RFQ/Messaging | API routes + polling (چت بعداً WebSocket) |
| Order/Funds | State machines صریح (XState-style) + LedgerEvent append-only |
| Compliance Gate | سرویس عرضی با جدول ComplianceRecord + قواعد CMP-002 |
| Documents | MinIO + metadata در Postgres |
| Search/i18n/SEO | Postgres FTS + next-intl + SSR |

## ریسک‌ها

تحریم سرویس‌های بیلد/CDN (npm/CDN جایگزین لازم — `عرف`)؛ نگهداری سرور؛ شریک escrow هنوز ندارد (FIN-002 حالت ۳ پیش‌فرض MVP).

## T14

تصمیم نهایی صاحب‌کار؛ بازبینی پس از MVP؛ هر تغییر = ADR جدید.

## خودآزمایی

هر ADR به قید accepted وصل است؛ جایگزین‌ها با دلیل رد شدند؛ هیچ وابستگی تحریم‌ریسکی پیش‌فرض نیست ✓

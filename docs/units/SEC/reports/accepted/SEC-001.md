## ۱) نقش‌ها و دسترسی (Roles)

| نقش | دسترسی | کنترل |
|---|---|---|
| مهمان | فقط عمومی | گیت CMP روی اقدامات |
| خریدار/تأمین‌کننده | داده خودشان | مالکیت داده (LEG-004) |
| کارگزار/حمل | اسناد سفارش خودش | حداقل‌سازی |
| پشتیبانی CS | تیکت + داده حداقلی ماسک‌شده | لاگ دسترسی (01-AGENT-IDENTITY) |
| CMP | پرونده انطباق، بدون داده پرداخت کامل | انسان در حلقه |
| Admin | تفکیک وظایف (SoD): هیچ ادمینی هم استعلام مالی هم آزادسازی | دو-کلید برای آزادسازی وجوه (FIN-002) |

## ۲) اسرار (Secrets)

- کلیدها/رمزها فقط در مدیریت اسرار (vault)؛ هرگز در کد/گیت/لاگ؛
- توکن‌های دسترسی GitHub/بانک: هرگز در URL یا لاگ (الگوی نشست ما: extraheader سرخود، بدون ذخیره)؛
- چرخش دوره‌ای + حداقل اختیار.

## ۳) سوءاستفاده (Abuse) — سناریوها و کنترل

| تهدید | کنترل |
|---|---|
| تقلب هویت فروشنده/خریدار | KYB/KYC سه‌لایه CMP-001 |
| پول‌شویی/پرداخت واسطه | گیت پرداخت CMP-002 + FATF پرچم‌ها |
| اسپم/RFQ جعلی | rate-limit + تایید تماس + غربال |
| دسترسی غیرمجاز به اسناد | RBAC + رمزنگاری در سکون/انتقال (`عرف`) |
| نفوذ ادمین | 2FA، SoD، لاگ غیرقابل حذف |
| chargeback تقلبی | FIN-002 نگهداشت نسبی |

## ۴) حسابرسی (Audit)

- audit trail همه‌جا (ADR A7 — ENG-001): هر تغییر حالت/دسترسی/داده = رکورد غیرقابل حذف؛
- رویدادهای مالی append-only (FIN-003)؛ گزارش دوره‌ای به GOV-001.

## ۵) پاسخ به حادثه (Incident Response)

```
شناسایی → مهار → اطلاع‌رسانی (متأثران/مراجع حسب قانون — نیازمند وکیل) → ریشه‌یابی → درس‌آموخته
```
- نقش‌ها: مسئول incident (GOV-001)، فنی (ENG)، حقوقی (LEG)؛ تمرین سالانه (`عرف`).
- حوادث مرتبط تحریم/داده: اطلاع CMP/LEG فوری.

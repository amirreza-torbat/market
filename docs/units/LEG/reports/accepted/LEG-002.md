# LEG-002 — بسته قرارداد تجاری (PO / PI / NDA / قالب ادعا)

- واحد: `LEG` | تسک: `LEG-002` | تاریخ: 2026-09-27
- وضعیت گزارش: done (پذیرش MGT 2026-09-27 — رأی QA: reviews/LEG-002-r1.md)
- معیار پذیرش رجیستری: «PO PI NDA claim templates — Jurisdiction language dispute and force majeure covered»
- **اعلان:** همه اسناد اینجا «قالب پیش‌نویس برای بازبینی وکیل» هستند؛ هیچ قالبی بدون تأیید وکیل قابل استفاده نیست. مبنای ساختار: الگوبند «واسطه با وظایف KYB» (LEG-001)، چرخه اسنادی TRD-003، متادیتای مقصد TRD-013.

## ۱) سلسله‌مراتب اسناد در معامله نمونه

```
NDA (پیش از مذاکره) → PI (پیش‌فاکتور/عرضه) → PO (سفارش خرید مشتری) → قرارداد اصلی/تمامیات → اسناد حمل و پرداخت (TRD-003) → در صورت اختلاف: قالب ادعا/مذاکره → داوری/دادگاه
```

## ۲) PO — سفارش خرید (قالب)

- طرف‌ها: خریدار ↔ فروشنده (پلتفرم فقط «واسطه ثبت‌شده» — بند نقش صریح طبق LEG-001).
- فیلدها (اتصال TRD-014): شرح کالا + HS، مقدار/واحد/وزن، قیمت و ارز، Incoterm (TRD-003)، مقصد + وضعیت گیت CMP (TRD-013)، مجوزهای لازم (TRD-005)، زمان تحویل، شرایط پرداخت (FIN-001)، امضاها.
- بندهای خاص (`نیازمند بازبینی وکیل`): تأیید سفارش با امضای دو طرف؛ لغو/تغییر فقط کتبی؛ اولویت PO بر PI در تعارض.

## ۳) PI — پیش‌فاکتور/عرضه (قالب)

- کارکرد: سند اظهار مبنای پرداخت/ثبت سفارش (TRD-004 گام ۲)؛ اعتبار محدود (مثلاً ۱۵ روز — `عرف-تجاری`).
- فیلدها: شماره/تاریخ، طرف‌ها، شرح + HS، قیمت واحد/کل و ارز، Incoterm + بندر/مرز، اعتبار پیش‌فاکتور، شرایط پرداخت، اتصال به PO.
- `نیازمند بازبینی وکیل`: قید «این PI بخشی از قرارداد نمی‌شود مگر با PO امضاشده».

## ۴) NDA — عدم افشا (قالب دوطرفه)

- تعریف اطلاعات محرمانه (شامل داده تجاری، قیمت، مشتری، مستندات فنی؛ استثنا: عمومی/قانونی/مستقل توسعه‌یافته).
- مدت تعهد (مثلاً ۲–۳ سال پس از فسخ — `عرف`)، جبران خسارت، قانون حاکم و مرجع اختلاف (بند مشترک ۶).
- `نیازمند بازبینی وکیل`: قلمرو اعتبار تعهد در حقوق ایران و اجراپذیری جریمه نقدی.

## ۵) قالب ادعا/شکایت (Claim & Dispute Template)

- مراحل: اعلان کتبی ظرف مهلت (مثلاً ۱۴ روز از تحویل/کشف نقص — `عرف`) → مستندات (عکس/گزارش بازرس — INSP) → مذاکره مهلت‌دار → داوری/دادگاه.
- فیلدها: طرف‌ها، شماره PO/PI، شرح نقص/تأخیر، مبنای ادعا، خواسته، اسناد پیوست.
- اتصال: حالت‌های استثنای مدل حمل (TRD-003: customs_hold، damaged، docs_rejected) و Payment Protection (FIN-001).

## ۶) بندهای مشترک الزامی (معیار پذیرش رجیستری)

| بند | محتوای قالب | برچسب |
| --- | --- | --- |
| **قانون حاکم** | انتخاب حقوق حاکم + صراحت؛ برای پلتفرم: حقوق ایران برای رابطه پلتفرم-کاربر؛ تجاری: حسب توافق طرف‌ها | `نیازمند وکیل` |
| **زبان** | زبان غالب سند (مثلاً فارسی/انگلیسی دوزبانه با نسخه حاکم)؛ ترجمه صرفاً کمک | `نیازمند وکیل` |
| **حل اختلاف** | پله‌ای: مذاکره (X روز) → داوری موسسه/قواعد توافقی → دادگاه صالح؛ مقر/زبان داوری | `نیازمند وکیل` |
| **Force Majeure** | تعریف (بلای طبیعی، جنگ، تحریم جدید مقرراتی، تعطیلی مرز — پیوند TRD-006..012 گیت‌ها)؛ اعلان ظرف مهلت؛ تعلیق تعهدات؛ فسخ در تداوم | `نیازمند وکیل` — نکته: «تحریم» به‌عنوان نیروی قهری فقط اثر قراردادی دارد، نه مجوز هیچ اقدام دورزننده |
| **گیت‌های انطباق** | شرط صریح: تعهدات با رعایت قوانین صادرات/واردات و CMP؛ تخلف = حق توقف | مطابق TRD-006..012 |
| **حمل/ریسک** | ارجاع به Incoterm قرارداد + نقاط انتقال (TRD-003) | `نیازمند وکیل` |

## ۷) اتصال به چرخه پلتفرم (پیشنهاد محصول)

- هر قالب = رکورد قابل تولید از سفارش (فیلدهای TRD-014 خودکار پر شوند)؛ امضای دیجیتال/الکترونیکی طبق ق.ت.ا ۱۳۸۲ (LEG-001) — `نیازمند وکیل`.
- نسخه‌بندی قالب‌ها + تاریخ اعتبار + محرک بازنگری (تغییر قانون/تصمیم وکیل).

## مجهولات و محرک بازنگری

- تأیید وکیل روی هر قالب (پیش‌شرط استفاده)؛ متن رسمی ق.ت.ا (قفل LEG-001)؛ قواعد داوری انتخابی.
- بازنگری: تغییر LEG-001 الگوبند، تغییر قوانین، یافته TRD-013 جدید.
